# 04-CRM 客戶關係管理系統

**完全以自然語言描述需求，透過 Codex的對話(Review Agent)、與對話(Development Agent)，未使用ChatGpt 。**

**此專案，完全由codex開發，無人為寫任何程式碼，OpenAI pro 100美金帳戶。**

**測試步驟: 位於  04-CRM_維護作業詳細測試步驟_v1.0.docx

**獨立執行程式: 位於資料夾 CRM-Windows-x64-1.2.1


繁體中文桌面瀏覽器系統，用來管理公司客戶、聯絡人、詢問、商機、實際互動及追蹤待辦。

目前程式版本為 **1.2.1**，業務範圍為第一階段。系統在本機執行，透過個人帳號登入使用。

## 選擇啟動方式

| 項目 | Windows 獨立執行版 | 原始碼版 |
| --- | --- | --- |
| 適用情況 | 直接使用已匯出的系統包 | 在專案內使用、維護或開發 |
| 啟動檔案 | 解壓縮後的 `CRM/CRM.exe` | 專案根目錄的 `Start-CRM.cmd` |
| Python 環境 | 不需另外安裝 | 需要 Python 與專案套件 |
| 預設資料位置 | `CRM.exe` 旁的 `data` 資料夾 | 專案內的 `.runtime` 資料夾 |
| 本機網址 | 以啟動視窗顯示的網址為準 | [http://127.0.0.1:18040/](http://127.0.0.1:18040/) |

兩種方式各自使用自己的資料。獨立執行版的程式包不會自動帶入原始碼版的帳號或業務紀錄。

## Windows 獨立執行版

### 第一次使用

1. 取得 `CRM-Windows-x64.zip`；若本專案已完成建置，可使用 [獨立版程式包](dist/portable/CRM-Windows-x64.zip)，也可由系統內的匯出按鈕下載。
2. 將 ZIP **完整解壓縮**到有寫入權限的資料夾，再開啟其中的 `CRM` 資料夾。
3. 雙擊 `CRM.exe`。
4. 首次啟動時，在啟動視窗設定第一位員工的登入帳號，並輸入兩次密碼。輸入密碼時不會顯示字元；系統沒有預設帳號或預設密碼。
5. 系統會自動開啟瀏覽器，使用剛設定的帳密登入。

首次啟動會在 `CRM.exe` 旁建立 `data` 資料夾，保存這套系統自己的資料庫與秘密金鑰，不建立示範業務資料。

### 再次啟動與停止

日後直接執行同一份 `CRM.exe`，就會繼續使用原本 `data` 中的資料。

使用期間請保留啟動視窗。關閉瀏覽器只會離開畫面；在啟動視窗按 `Ctrl+C` 或關閉啟動視窗，才會停止系統。

獨立版優先使用本機埠 `18040`；若該埠已被使用或無法使用，會自動選擇其他可用埠。**請以當次啟動視窗顯示、或自動開啟的網址為準**，不要只沿用上一次的瀏覽器書籤。

獨立版不需安裝 Python、Django 或開發工具；目前提供 Windows x64 程式包，已驗證環境為 Windows 11。包內另附 [使用說明](portable/使用說明.txt) 與第三方授權文件。

## 原始碼版啟動

1. 在專案根目錄雙擊 [Start-CRM.cmd](Start-CRM.cmd)。
2. 若尚無專案虛擬環境，啟動程式會透過 `python` 建立 `.venv`；需要安裝套件時，須能下載 [requirements.txt](requirements.txt) 中的套件。
3. 若資料庫尚無員工帳號，依啟動視窗提示自行設定第一位員工的帳號與密碼。
4. 等待顯示本機啟動訊息，再開啟 [CRM 本機網址](http://127.0.0.1:18040/)。

也可以在專案根目錄的 PowerShell 執行：

```powershell
.\Start-CRM.cmd
```

或直接呼叫啟動腳本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-CRM.ps1
```

上述執行原則只套用到該 PowerShell 程序，不變更全機設定。首次建立環境前，電腦須已安裝 Python，且可使用 `python` 指令；本專案開發端使用 Python 3.14.7。

啟動程式會套用資料結構遷移；對已有資料的環境進行版本更新前，請先依下方方式備份。原始碼版使用本機開發服務，執行期間需保留服務視窗；按 `Ctrl+C` 可停止。若啟動程式提示 CRM 已在執行，則沿用既有服務。

目前網址使用 **18040**；舊的 `8040` 在已驗證的 Windows 環境被系統保留，請勿沿用舊網址。`127.0.0.1` 代表目前這台電腦，本專案目前沒有對外公開或區域網路部署。

## 個人帳號與權限

第一位初始化員工具備三項獨立特殊授權，可在「員工帳號」建立其他員工的個人帳號、設定密碼及授權。

| 授權 | 可執行的額外操作 |
| --- | --- |
| 全域編輯 | 編輯其他人建立或負責的核心業務紀錄 |
| 責任轉交 | 指定新負責人，並明確選取要轉交的工作 |
| 帳號管理 | 管理員工帳號與特殊授權，並使用「匯出獨立可執行系統」 |

所有已啟用並登入的員工都能建立及查看核心業務紀錄。一般編輯須為該筆紀錄的建立者、目前負責人，或具「全域編輯」授權。這三項特殊授權各自獨立，不會因取得其中一項就自動取得其他項。

新建業務紀錄的建立者與初始負責人均為目前登入者。責任轉交只處理確認選取的項目，保留原建立者與歷程；原建立者仍保有一般編輯資格。

## 日常操作

登入後可由左側選單開啟各模組，從列表查詢、新增或進入紀錄詳情。

| 模組 | 使用方式與重點 |
| --- | --- |
| 工作總覽 | 查看公司數、商機目前狀態與階段分布、今日到期及逾期未完成待辦；日期依 `Asia/Taipei` 計算 |
| 公司 | 管理公司客戶資料，查看相關聯絡人、詢問、商機及往來脈絡 |
| 聯絡人 | 記錄聯絡方式與目前隸屬公司；可暫無隸屬公司，變更隸屬時保留歷史 |
| 詢問 | 先保存已知需求及聯絡資訊，再確認資格或結束詢問；不強迫先建立公司或商機 |
| 商機 | 每筆指定一個主要公司，可選多位參與聯絡人，維護銷售階段與目前狀態 |
| 實際互動 | 記錄已實際發生的往來，儲存時須明確確認事實已發生 |
| 追蹤待辦 | 安排後續工作、到期日及完成或取消狀態，與實際互動分開保存 |
| 員工帳號 | 具「帳號管理」授權者可維護個人帳號及各項授權 |

### 儲存、取消與搜尋

- 編輯完成後按「儲存」；確認狀態變更時按「確認」。驗證失敗會在欄位及提交按鈕旁顯示訊息。
- 按「取消」會丟棄目前尚未儲存的內容，保留已儲存紀錄。「取消工作」則是變更業務狀態的操作，須進入確認畫面後提交。
- 列表可依名稱、內容或完整識別搜尋；依模組提供狀態、階段及負責人篩選。
- 紀錄若已被其他人修改，請重新開啟最新內容再編輯；不要直接覆蓋他人的變更。

### 商機與關聯資料

商機的銷售階段依序為 **需求確認 → 方案討論 → 議價**。進行中的商機可依實際情況前進或退回階段，不要求一定走完全部階段才確認結果。

商機目前狀態分為「進行中」、「暫緩」、「已取消」、「成交」、「未成交」。「成交」與「未成交」都須由人員明確確認並填寫原因；**「未成交」指已確認的結束結果，不能用來表示仍在追蹤的商機**。暫緩後可恢復進行；已取消、成交或未成交的商機可重開，保留同一識別與先前歷程。非進行中的商機須先恢復進行或重開，再調整階段。

詢問可不連公司或商機，也可只連其中一項；兩者都有填寫時，公司須與該商機的主要公司一致。商機的參與聯絡人不要求都隸屬於該主要公司。

實際互動與追蹤待辦各自最多選一個主要業務主題：公司、詢問或商機；內部事項可不指定主題。完成待辦不會自動產生一筆實際互動，實際發生後應另行記錄。

### 公司停用與歷史

停用公司會保留公司及既有關聯紀錄，並列出受影響的未完成工作供確認處理，不會自動刪除歷史或取消工作。停用後續辦既有工作須有明確續辦依據；新增商機前須先啟用公司。

確認續辦不會自動啟用公司，也不會額外授予編輯權。需要變更負責人時，應由具「責任轉交」授權者執行。

## 匯出獨立可執行系統

1. 使用具「帳號管理」授權的個人帳號登入。
2. 按右上角「匯出獨立可執行系統」。
3. 閱讀匯出範圍後按「下載獨立系統 ZIP」；按「取消」可返回工作總覽。
4. 將下載的 ZIP 完整解壓縮，依前述步驟執行 `CRM.exe`。

匯出的 ZIP 只包含下列四個項目：

```text
CRM/
├─ CRM.exe
├─ 使用說明.txt
├─ THIRD-PARTY-NOTICES.txt
└─ release.json
```

這是**全新系統程式包**，不包含目前帳號、密碼、客戶資料、業務歷程、資料庫、秘密金鑰或對話附件。首次使用需自行設定新帳密；匯出操作會留下可歸責的操作歷程。

獨立版內也可再次匯出全新程式包。**匯出按鈕不會備份現有資料**；要保留既有紀錄，請保存下節說明的資料目錄。

## 資料保存、備份與搬移

以下為未自訂資料路徑時的預設位置：

| 執行方式 | 資料庫 | 秘密金鑰 |
| --- | --- | --- |
| 原始碼版 | `.runtime/crm.sqlite3` | `.runtime/secret.key` |
| 獨立執行版 | `CRM.exe` 旁的 `data/crm.sqlite3` | 同一個 `data/secret.key` |

安全備份步驟：

1. 讓使用者完成儲存並停止系統服務，確認啟動視窗中的程序已結束。
2. 將整個 `.runtime` 或 `data` 資料夾複製到受保護的備份位置，同時保留當時使用的程式版本。
3. 保留資料庫與秘密金鑰的對應關係；不要刪除或重新產生金鑰來重置系統。

獨立版搬移時，先停止系統，再將完整 `CRM` 資料夾（包含 `CRM.exe` 與自己的 `data`）一起移動，從新位置重新啟動。若從備份還原，先停止服務並另存目前資料，再以同版本程式配合同一份完整備份目錄還原；不要直接覆蓋正在使用的資料庫。

若必須在服務運作中備份，需採用 SQLite 一致性備份方式，並保護對應金鑰；不要只複製正在寫入的資料庫檔案。業務資料、帳號、金鑰與備份不應加入版本控制或放進可公開下載的程式包。

## 常見問題

| 情況 | 處理方式 |
| --- | --- |
| 瀏覽器顯示拒絕連線 | 確認 CRM 服務已啟動且啟動視窗仍在執行，再使用視窗顯示的網址；原始碼版使用 `18040` |
| 獨立版每次開啟的網址不同 | 預設埠可能被其他服務使用，請使用當次顯示的網址；資料仍由原本的 `data` 保存 |
| 瀏覽器沒有自動開啟 | 手動複製啟動視窗顯示的完整網址到本機瀏覽器 |
| 找不到匯出按鈕或「員工帳號」 | 確認目前帳號是否有「帳號管理」授權；僅有「全域編輯」不足以使用這兩項功能 |
| 可以查看卻不能編輯 | 確認是否為建立者、目前負責人或具全域編輯權；停用公司相關工作也須符合續辦條件 |
| 系統包匯出失敗 | 查看下載按鈕旁的訊息；原始碼版需具備完整且版本相符的建置產物，維護者可依下節重新建置 |
| 原始碼版無法建立 Python 環境 | 在 PowerShell 確認 `python` 指令可用，並檢查套件下載連線與啟動視窗的錯誤訊息 |
| 獨立版提示既有資料需要版本升級 | 先保留資料並備份，交由維護者處理相容性與遷移；不要刪除 `data` 或以空白資料取代 |

## 維護與建置

以下指令供維護者在專案根目錄使用。一般使用獨立版不需要執行。

### 技術組成

開發端已使用 Python 3.14.7、Django 5.2.19 與 SQLite；獨立版內含 Python 執行環境及 Waitress 3.0.2。執行套件版本記錄於 [requirements.txt](requirements.txt)，封裝工具版本記錄於 [requirements-build.txt](requirements-build.txt)。

### 重新建置 Windows 獨立版

先完成原始碼環境設定，再於 Windows x64 執行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe tools\build_portable.py
```

建置腳本為 [tools/build_portable.py](tools/build_portable.py)，封裝設定為 [tools/CRM.spec](tools/CRM.spec)。產物位於：

```text
dist/portable/
├─ CRM.exe
├─ CRM-Windows-x64.zip
└─ release.json
```

第三方授權隨 ZIP 一起提供；目標電腦不需安裝封裝工具。請透過建置腳本產生程式包，避免直接壓縮含資料庫、金鑰及私有附件的整個專案。

### 隔離驗證

自動測試指令：

```powershell
.\.venv\Scripts\python.exe manage.py test crm.tests --noinput
```

預設測試資料庫為 `.qa/test.sqlite3`，與業務資料庫分開。不可將 `CRM_TEST_DB` 指向實際業務資料庫；設定會拒絕兩者使用相同路徑。進行其他 QA 時也應使用隔離資料目錄與測試帳號。

桌面瀏覽器驗證腳本為 [qa/browser_acceptance.py](qa/browser_acceptance.py)；實際 ZIP 下載、EXE 啟動、重啟及再次匯出驗證為 [qa/portable_acceptance.py](qa/portable_acceptance.py)。兩者需要執行腳本的 Python 環境已備妥 Playwright 與 Chromium，QA 產物保存在 `.qa`。

獨立版支援 `--data-dir` 指定自己的資料目錄、`--port` 指定本機埠（`0` 表示自動選擇），以及 `--no-browser` 不自動開啟瀏覽器。原始碼版可使用 `CRM_DATA_DIR` 或 `CRM_DB` 指向隔離環境；環境提供的 `CRM_SECRET_KEY` 須另行保護。自訂路徑後，備份應依實際資料位置處理。
